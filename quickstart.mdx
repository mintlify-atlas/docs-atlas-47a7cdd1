There are two ways to set up a Rust-GPU shader project locally. The recommended approach — and the one covered in this guide — is to use the `spirv-builder` crate inside a `build.rs` build script. It automates the process of invoking `rustc_codegen_spirv`, handles Cargo dependency tracking, and exposes the compiled `.spv` path as an environment variable your application can read at compile time. The alternative approach, using a manually configured `.cargo/config` file, is described at the end of this page for those who prefer a lower-level setup or do not need automatic recompilation.

<Warning>
  Build dependencies are compiled in **debug mode** by default. This means
  `rustc_codegen_spirv` — which is a substantial Rust compiler component — will
  be built unoptimized and will be **extremely slow**. Add the build-override
  profiles shown in Step 2 to your workspace `Cargo.toml` to fix this before
  running your first build.
</Warning>

<Steps>

<Step title="Copy rust-toolchain.toml">

Rust-GPU requires an exact nightly version of the Rust toolchain. The build will
fail with a descriptive error message if you use the wrong version, so the easiest
fix is to copy the `rust-toolchain.toml` file from the rust-gpu repository into
the root of **your project**. This file pins the toolchain for everyone working
on the project automatically via `rustup`.

Copy the file from the [rust-gpu repository](https://github.com/EmbarkStudios/rust-gpu/blob/main/rust-toolchain.toml) or create it with the following content:

```toml
[toolchain]
channel = "nightly-2023-09-30"
components = ["rust-src", "rustc-dev", "llvm-tools"]
```

The `rust-src`, `rustc-dev`, and `llvm-tools` components are required by
`rustc_codegen_spirv` to build the compiler backend and cross-compile the Rust
core library for the SPIR-V target.

</Step>

<Step title="Add spirv-builder to your application">

In your **application** crate's `Cargo.toml` (not the shader crate), add
`spirv-builder` as a build dependency and configure the build-override profiles
to ensure the compiler backend is always built in release mode:

```toml
[build-dependencies]
spirv-builder = "0.9"
```

Then add the following profile overrides to your **workspace** `Cargo.toml` (or
your application's `Cargo.toml` if you are not using a workspace). These compile
all build-script dependencies with optimizations, which is essential for
reasonable compile times:

```toml
# Compile build-dependencies in release mode with
# the same settings as regular dependencies.
[profile.release.build-override]
opt-level = 3
codegen-units = 16

[profile.dev.build-override]
opt-level = 3
```

> This optimizes **all** build-script dependencies, not just `spirv-builder`.
> See [issue #448](https://github.com/EmbarkStudios/rust-gpu/issues/448) for
> important caveats about this approach.

All dependent crates (`spirv-builder`, `spirv-std`, `rustc_codegen_spirv`) are
published on [crates.io](https://crates.io).

</Step>

<Step title="Create build.rs">

Create a `build.rs` file in the root of your application crate with the
following content. Replace `"shader-crate"` with the relative path from your
application's `Cargo.toml` to your shader crate directory, and replace the
`target` string with the SPIR-V environment you are targeting.

```rust
use spirv_builder::{MetadataPrintout, SpirvBuilder};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    SpirvBuilder::new("shader-crate", "spirv-unknown-vulkan1.1")
        .print_metadata(MetadataPrintout::Full)
        .build()?;
    Ok(())
}
```

Common values for the `target` parameter:

| Target string | Environment |
|---|---|
| `"spirv-unknown-vulkan1.1"` | Vulkan 1.1 (recommended) |
| `"spirv-unknown-vulkan1.2"` | Vulkan 1.2 |
| `"spirv-unknown-vulkan1.1spv1.4"` | Vulkan 1.1 + SPIR-V 1.4 |
| `"spirv-unknown-spv1.5"` | Raw SPIR-V 1.5 |
| `"spirv-unknown-webgpu0"` | WebGPU |

See the [Platform Support](/platform-support) page for the full list of
available target triples.

`MetadataPrintout::Full` instructs `spirv-builder` to emit a Cargo environment
variable (`<shader_crate>.spv`) pointing to the compiled SPIR-V binary so you
can load it with `include_bytes!`.

</Step>

<Step title="Write a shader crate">

Create a separate Cargo crate for your shaders. In the shader crate's
`Cargo.toml`, configure it as a `dylib` (required by `rustc_codegen_spirv`) and
add `spirv-std` as a dependency:

```toml
[lib]
crate-type = ["dylib"]

[dependencies]
spirv-std = { version = "0.9" }
```

Then write your shader in `src/lib.rs`. The crate must use `#![no_std]` because
the SPIR-V execution environment does not have an operating system. The
`#[spirv(fragment)]` attribute marks the function as a fragment shader
entry-point. This example outputs solid red:

```rust
#![no_std]

use spirv_std::spirv;
use spirv_std::glam::{vec4, Vec4};

#[spirv(fragment)]
pub fn main_fs(output: &mut Vec4) {
    *output = vec4(1.0, 0.0, 0.0, 1.0);
}
```

The `output: &mut Vec4` parameter is the first color attachment output. The
`glam` vector types are available because `spirv-std` enables `glam` support by
default.

</Step>

<Step title="Load the compiled shader in your application">

After `build.rs` runs successfully, `spirv-builder` writes the path of the
compiled `.spv` binary into a Cargo environment variable. Load it into your
application at compile time using `include_bytes!`:

```rust
const SHADER: &[u8] = include_bytes!(env!("shader_crate.spv"));
```

<Note>
  If your shader crate's **package name** contains hyphens (e.g.
  `my-shader-crate`), the environment variable name will use **underscores**
  instead (e.g. `my_shader_crate.spv`). Cargo normalizes package names this
  way for environment variables.
</Note>

Pass the `SHADER` byte slice to your graphics API's shader module creation
function (e.g. `vkCreateShaderModule` in Vulkan, `device.create_shader_module`
in wgpu).

</Step>

</Steps>

## Alternative: Using `.cargo/config`

If you want to build a shader crate directly with `cargo build` without a build
script — for example, when experimenting or contributing to rust-gpu itself —
you can configure the target and compiler flags manually.

<Note>
  This method requires you to **manually rebuild rust-gpu** each time the
  repository changes. It is not recommended for production integrations.
</Note>

First, clone the rust-gpu repository and build the compiler backend:

```bash
git clone https://github.com/EmbarkStudios/rust-gpu.git
cd rust-gpu
cargo build --release
```

This produces a `librustc_codegen_spirv` dynamic library in `target/release/`.
Keep this file somewhere stable that you can reference from your shader project.

Next, create a `.cargo/config.toml` file at the root of your shader project.
Replace `<path_to_librustc_codegen_spirv>` with the absolute path to the
dynamic library you just built:

```toml
[build]
target = "spirv-unknown-spv1.3"
rustflags = [
    "-Zcodegen-backend=<path_to_librustc_codegen_spirv>",
    "-Zbinary-dep-depinfo",
    "-Csymbol-mangling-version=v0",
    "-Zcrate-attr=feature(register_tool)",
    "-Zcrate-attr=register_tool(rust_gpu)"
]

[unstable]
build-std = ["core"]
build-std-features = ["compiler-builtins-mem"]
```

Then build your shader crate with:

```bash
cargo build
```

The compiled SPIR-V file will be written to `target/debug/<project_name>.spv`.

## Running the Examples

The rust-gpu repository includes several ready-to-run examples demonstrating
different shaders and rendering backends. The examples are organized into two
groups:

**Shader crates** (`examples/shaders/`):
- `sky-shader` — a procedural sky rendered with the Preetham atmospheric model
- `simplest-shader` — minimal vertex and fragment shader
- `compute-shader` — GPU compute example
- `mouse-shader` — interactive shader reacting to mouse position

**Runner crates** (`examples/runners/`):
- `wgpu` — cross-platform runner using the wgpu graphics API
- `ash` — Vulkan runner using the ash bindings
- `cpu` — software-rendered CPU runner for debugging without a GPU

To run the wgpu example with the sky shader:

```bash
cargo run --bin example-runner-wgpu
```

To run the Vulkan (ash) example:

```bash
cargo run --bin example-runner-ash
```

To run the CPU software renderer:

```bash
cargo run --bin example-runner-cpu
```

All examples must be run from the root of the rust-gpu repository so that the
`rust-toolchain.toml` file is picked up automatically.
